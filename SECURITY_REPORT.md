# Отчёт по проверке безопасности (данные никуда не сливаются)

## Итог

**Внешняя отправка данных:** данные уходят только туда, где это задумано — в **Google Gemini** (транскрипция и оценка) и в **Telphin** (история звонков и скачивание записей). Сторонних аналитик, трекеров или посторонних API в коде нет.

**Риски:** открытый API без авторизации (доступ у того, кто знает URL), возможная утечка фрагментов текста в логи при ошибках. Рекомендации и исправления — ниже.

---

## 1. Секреты и конфигурация

| Проверка | Статус |
|----------|--------|
| `backend/.env` в `.gitignore` | ✅ Файл игнорируется, в репозиторий не попадёт |
| Секреты в коде | ✅ Нет хардкода ключей; используются переменные окружения |
| Эндпоинт `/api/config/check` | ✅ Возвращает только «configured»/«missing», не сами ключи |

**Рекомендация:** Никогда не коммитить `backend/.env`. Если он когда-либо попадал в историю git — смените GEMINI_API_KEY и креды Telphin и занесите новые значения только в окружение (не в репозиторий).

---

## 2. Куда уходят данные

| Направление | Что уходит | Зачем |
|-------------|------------|--------|
| **Google Gemini API** | Аудио (транскрипция), текст расшифровки (оценка) | Транскрипция и оценка по чек-листу — штатный функционал |
| **Telphin API** (apiproxy.telphin.ru) | App ID и Secret только для OAuth; далее — запросы истории и URL записей | Синхронизация звонков — штатный функционал |

Других внешних запросов (аналитика, трекинг, посторонние API) в проекте нет. Фронтенд ходит только на свой бэкенд (`NEXT_PUBLIC_API_URL`).

---

## 3. Логирование (исправлено)

**Было:** В `evaluation_service.py` в логи писались первые 300 символов ответа модели и при ошибке парсинга — полный ответ. В ответе модели могут быть фрагменты расшифровки звонков — то есть персональные/конфиденциальные данные.

**Сделано:** Логирование изменено: не пишем содержимое ответа модели, только длину и факт ошибки парсинга (без текста ответа). Так данные из звонков не попадают в логи.

---

## 4. API без авторизации

Сейчас все эндпоинты API доступны без логина и токена. Тот, кто знает URL бэкенда, может:

- получать список звонков и детали по каждому (включая расшифровки);
- экспортировать данные;
- запускать синхронизацию Telphin (если креды настроены на бэкенде).

То есть «утечка» возможна не из-за отправки данных на сторонние сервера, а из-за открытого доступа к самому API.

**Рекомендации:**

- В продакшене ограничить доступ к бэкенду: firewall, VPN или доступ только с доверенных IP (например, только с Vercel, если фронт там).
- Либо позже добавить авторизацию (API-ключ, JWT или Basic Auth) и не отдавать данные без проверки.

---

## 5. Прочее

- **CORS:** Настроен на конкретные источники (localhost и ваш домен фронта), не `*`.
- **Заголовки безопасности:** Включены X-Content-Type-Options, X-Frame-Options, X-XSS-Protection, Referrer-Policy.
- **Фронт в dev:** В консоль выводится только `API URL` (адрес бэкенда), не ключи и не данные звонков.

---

## Краткий чек-лист для вас

1. ✅ Данные не отправляются на посторонние сервисы — только Gemini и Telphin по назначению.
2. ✅ Логи не содержат расшифровок/ответов модели — правки внесены.
3. ⚠️ Секреты хранить только в переменных окружения, не коммитить `.env`.
4. ⚠️ В продакшене ограничить доступ к API (сеть/VPN или авторизация).
