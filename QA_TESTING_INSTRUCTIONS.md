# Инструкции по тестированию исправлений Gemini API

**Для:** Менеджер отдела качества  
**Дата:** Ноябрь 2025  
**Версия:** 1.0

---

## Цель тестирования

Проверить, что:
1. Система корректно работает с моделью `gemini-2.5-flash`
2. Обработка ошибок квот работает правильно
3. Повторные попытки выполняются при временных ошибках
4. Пользователи получают понятные сообщения об ошибках

---

## Подготовка к тестированию

### Требования

1. Доступ к тестовой/продакшн среде приложения
2. Валидный API ключ Gemini API (можно использовать free tier)
3. Аудио файл для тестирования транскрипции (формат: MP3, WAV или другой поддерживаемый формат)
4. Доступ к логам приложения (для проверки повторных попыток)

### Проверка конфигурации

Перед началом тестирования убедитесь, что в конфигурации используются правильные модели:

**Ожидаемые значения в переменных окружения:**
- `GEMINI_TRANSCRIPTION_MODEL=gemini-2.5-flash`
- `GEMINI_EVALUATION_MODEL=gemini-2.5-flash`

Если переменные не установлены, используются значения по умолчанию из `backend/config.py`.

## Сценарии тестирования

### Сценарий 1: Проверка работы транскрипции (Smoke Test)

**Цель:** Убедиться, что транскрипция работает с новой моделью.

**Шаги:**

1. Откройте интерфейс приложения
2. Загрузите аудио файл через компонент загрузки
3. Дождитесь завершения транскрипции
4. Проверьте, что транскрипция отображается корректно

**Ожидаемый результат:**
- ✅ Транскрипция выполняется успешно
- ✅ Текст транскрипции отображается в интерфейсе
- ✅ В логах нет ошибок 429 о недоступности модели

**Проверка логов:**
```
Проверьте логи на наличие сообщений:
- "Попытка транскрипции 1/5 для файла ..."
- "Транскрипция завершена успешно"
- НЕТ сообщений "Модель недоступна на free tier"
```

---

### Сценарий 2: Проверка работы оценки звонка (Smoke Test)

**Цель:** Убедиться, что оценка звонка работает с новой моделью.

**Шаги:**

1. После успешной транскрипции дождитесь автоматической оценки звонка
2. Проверьте, что оценка отображается в таблице результатов
3. Проверьте, что все критерии оценены корректно

**Ожидаемый результат:**
- ✅ Оценка выполняется успешно
- ✅ Результаты отображаются в таблице EvaluationTable
- ✅ В логах нет ошибок 429 о недоступности модели

**Проверка логов:**
```
Проверьте логи на наличие сообщений:
- "Попытка оценки 1/5"
- "Итоговая оценка: X из Y возможных"
- НЕТ сообщений "Модель недоступна на free tier"
```

---

### Сценарий 3: Проверка обработки временной ошибки квоты (429)

**Цель:** Убедиться, что система корректно обрабатывает временные ошибки квот с повторными попытками.

**Подготовка:**

Для этого теста можно использовать один из подходов:

**Вариант А (если возможно):** Временно установить неверный API ключ или модель с ограниченной квотой, чтобы вызвать ошибку 429.

**Вариант Б:** Проверить логи на наличие случаев, когда система уже обрабатывала ошибки 429.

**Шаги:**

1. Вызовите ситуацию, при которой Gemini API вернёт ошибку 429 (временное превышение квоты)
2. Наблюдайте за поведением системы
3. Проверьте логи приложения

**Ожидаемый результат:**
- ✅ Система не падает с ошибкой сразу
- ✅ Выполняются повторные попытки (до 5 попыток)
- ✅ Между попытками есть пауза (ожидание)
- ✅ Если ошибка временная, запрос в итоге выполняется успешно
- ✅ В логах видны сообщения о повторных попытках

**Проверка логов:**
```
Ожидаемые сообщения в логах:
- "Ошибка квоты API (попытка 1/5): ... Повтор через X сек..."
- "Попытка транскрипции 2/5 для файла ..." (или "Попытка оценки 2/5")
- Если успешно: "Транскрипция завершена успешно" (или "Итоговая оценка...")
```

---

### Сценарий 4: Проверка обработки ошибки "модель недоступна на free tier"

**Цель:** Убедиться, что система корректно обрабатывает ошибку недоступности модели без бесполезных повторных попыток.

**Подготовка:**

Временно измените модель в конфигурации на `gemini-2.0-flash` (которая недоступна на free tier) или используйте модель с квотой 0.

**Шаги:**

1. Измените `GEMINI_TRANSCRIPTION_MODEL` или `GEMINI_EVALUATION_MODEL` на модель, недоступную на free tier
2. Попробуйте выполнить транскрипцию или оценку
3. Проверьте поведение системы и логи

**Ожидаемый результат:**
- ✅ Система не выполняет бесполезные повторные попытки
- ✅ Пользователю показывается понятное сообщение об ошибке
- ✅ В сообщении указано название модели и рекомендация использовать другую модель
- ✅ В логах есть сообщение "Модель недоступна на free tier, повторная попытка не поможет"

**Проверка логов:**
```
Ожидаемые сообщения в логах:
- "Модель недоступна на free tier, повторная попытка не поможет: ..."
- НЕТ множественных попыток (только одна попытка)
```

**Проверка сообщения пользователю:**
```
Ожидаемое сообщение должно содержать:
- Название модели (например, "gemini-2.0-flash")
- Упоминание "недоступна на бесплатном тарифе"
- Рекомендацию использовать другую модель или перейти на платный тариф
```

---

### Сценарий 5: Проверка логирования и мониторинга

**Цель:** Убедиться, что все действия логируются корректно для отладки.

**Шаги:**

1. Выполните транскрипцию и оценку звонка
2. Проверьте логи приложения
3. Убедитесь, что логи содержат необходимую информацию

**Ожидаемый результат:**
- ✅ Все попытки логируются с указанием номера попытки (1/5, 2/5 и т.д.)
- ✅ При ошибках логируется причина ошибки
- ✅ При повторных попытках логируется время ожидания
- ✅ Успешные операции логируются с результатами

**Проверка логов:**
```
Примеры ожидаемых записей в логах:

Успешная транскрипция:
- "Попытка транскрипции 1/5 для файла ..."
- "Транскрипция завершена успешно, длина текста: X символов"

Успешная оценка:
- "Попытка оценки 1/5"
- "Итоговая оценка: X из Y возможных (Z%)"

При ошибке с повторной попыткой:
- "Ошибка квоты API (попытка 1/5): ... Повтор через X сек..."
- "Попытка транскрипции 2/5 для файла ..."
```

## Известные ограничения

1. **Тестирование ошибок 429:** Для полного тестирования обработки ошибок 429 может потребоваться создание условий, при которых Gemini API вернёт эту ошибку. В production это может происходить при высокой нагрузке.

2. **Free tier ограничения:** На бесплатном тарифе Gemini API есть ограничения по количеству запросов. При активном тестировании может быть достигнут лимит запросов.
