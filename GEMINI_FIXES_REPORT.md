# Отчёт об исправлениях Gemini API

**Дата:** Ноябрь 2025  
**Версия:** 1.0

## Краткое описание

Выполнена настройка сервиса для работы с Gemini API: изменена модель на доступную для free tier и улучшена обработка ошибок квот с автоматическими повторными попытками.

---

## Выполненные изменения

### 1. Изменение модели Gemini API

**Проблема:** Модель `gemini-2.0-flash` недоступна на бесплатном тарифе Gemini API (квота = 0), что вызывало ошибки 429.

**Решение:** Изменена модель по умолчанию на `gemini-2.5-flash`, которая доступна на free tier.

**Изменённые файлы:**
- `backend/config.py`
  - `GEMINI_TRANSCRIPTION_MODEL`: изменено на `gemini-2.5-flash`
  - `GEMINI_EVALUATION_MODEL`: изменено на `gemini-2.5-flash`

### 2. Улучшение обработки ошибок квот (429)

**Проблема:** При временных ошибках квот (rate limiting) система не выполняла повторные попытки, что приводило к сбоям при обработке запросов.

**Решение:** Добавлена автоматическая обработка ошибок 429 с повторными попытками и умным ожиданием.

**Изменённые файлы:**
- `backend/services/evaluation_service.py`
- `backend/services/transcription_service.py`

**Реализованные улучшения:**

1. **Автоматические повторные попытки:**
   - Количество попыток увеличено с 3 до 5
   - При ошибке 429 система автоматически повторяет запрос

2. **Умное ожидание:**
   - Если в сообщении об ошибке указано время ожидания (например, "retry in 60s"), система ждёт указанное время + 1 секунда
   - Если время не указано, используется exponential backoff: 2, 4, 8, 16 секунд

3. **Улучшенные сообщения об ошибках:**
   - Сообщения теперь содержат название модели, которая вызвала ошибку
   - Различаются ошибки "модель недоступна на free tier" и "временное превышение квоты"
   - Для ошибок "модель недоступна" повторные попытки не выполняются (бесполезно)

4. **Логирование:**
   - Все попытки логируются с указанием номера попытки
   - Логируются причины повторных попыток и время ожидания

## Технические детали

### Обработка ошибок 429

Система различает два типа ошибок квот:

1. **Модель недоступна на free tier** (квота = 0):
   - Определяется по наличию "limit: 0" или "free_tier" в сообщении об ошибке
   - Повторные попытки не выполняются
   - Пользователю показывается понятное сообщение с рекомендацией использовать другую модель

2. **Временное превышение квоты** (rate limiting):
   - Определяется по коду 429 или наличию "quota"/"limit" в сообщении
   - Выполняются повторные попытки с ожиданием
   - Если в ошибке указано время ожидания, используется оно; иначе — exponential backoff

### Функция извлечения времени ожидания

Добавлена функция `_extract_retry_after()`, которая парсит сообщение об ошибке и извлекает время ожидания в формате "retry in Xs".
