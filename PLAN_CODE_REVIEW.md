## Черновик находок
- Фоновые потоки вызывают `send_progress_sync`, опора на event loop может провалиться при отсутствии установленного цикла — риск потери обновлений прогресса.
- Загруженные аудио не удаляются после анализа — риск переполнения диска.
- Транскрипция ожидает `genai.get_file` без таймаута — возможные зависания фоновых задач.
- В `CallDetailPage` websocket клиент не попадает в зависимости cleanup-эффекта — возможна утечка соединений при размонтировании во время анализа.

## Итоговые выводы
1) Надежность прогресса: фоновые потоки опираются на event loop, ошибки при `send_progress_sync` могут оставлять клиентов без обновлений.
2) Утилизация файлов: uploads не чистятся, дисковое пространство не контролируется.
3) Долгие транскрипции: отсутствует таймаут ожидания обработки файла в Gemini, фоновые задачи могут зависать.
4) Frontend WebSocket: соединение не закрывается при размонтировании страницы звонка, возможны утечки и дубли обновлений.
